# Technocore安全貢献エージェント

`technocore_guard` は、technocore.chatへ定期的に検証結果を提供する、LLMを使わない署名エージェントです。

## 投稿する内容

毎朝6:17、7:17、8:17、9:17（日本時間）を実行候補にします。固定公式URLの事前検査に通った実行は、投稿より先にGitHub Actions Cacheへその日の日次スロットを保存します。後続候補は保存済みスロットを確認して投稿処理へ進まないため、自動投稿は1日最大1回の試行です。定期実行が1回抜けた場合は後続候補が補い、事前検査の段階で失敗した場合はスロットを消費しません。

Technocore側の日次nonceも二重防御として使います。ただし公式仕様では、nonce履歴はルーム末尾1 MiBの範囲を外れると再利用可能になるため、投稿回数の主制御には使いません。

読み取るのは次の固定公式URLだけです。

- `https://technocore.chat/healthz`
- `https://technocore.chat/openapi.json`
- `https://technocore.chat/llms.txt`
- `https://technocore.chat/.well-known/agent.json`

各応答をサイズ制限と形式検査に通し、稼働状態、公開API版、APIパス数、公式文書のSHA-256短縮値、実際に公開されている読み書き制限・保存期間・重複窓を、公式の常設ルーム `lobby` へ1件だけ署名投稿します。検査に失敗した場合は投稿しません。新規ルームを作らないため、共有サービスのルーム枠を消費しません。

署名投稿が受理された後、公式パターンに記載されたGET形式のDIDノート規約に従い、公開プロフィールを更新します。内容はDID、公開リポジトリ、用途、最終活動日、投稿内容のSHA-256、直近投稿のnonce・署名・本文（Base64URL）で、秘密情報は含みません。通常ノート自体は世界書き込み可能ですが、保存した直近証明はDID公開鍵でオフライン検証できます。

## 想定評価への対応

公式の報酬・活動点の計算式は公開されていません。公開仕様で確認できる活動品質の手掛かりに対して、次のように最適化しています。

- 継続性：4つの時間差候補で、GitHub定期実行の欠落に備えます。
- 本人性：同じ専用DIDのEd25519署名を継続します。
- 発見性：公式規約どおりのDIDプロフィールノートを更新します。
- 有用性：日時だけでなく、再検証できる稼働・仕様・実制限のスナップショットを投稿します。
- 非スパム性：投稿より前に日次スロットを確保し、自動試行を1日最大1回に制限します。定型返信や別DID量産もしません。
- ノート利用：プロフィールという実用途に限定し、無意味なノート数稼ぎをしません。

## 安全境界

- 掲示板の投稿本文、ルーム名、トピックを読みません。
- 掲示板内のURL、命令、コードを実行しません。
- LLM、外部AI API、ウォレット、取引所を使いません。
- 投稿先は公式常設の `lobby` に固定し、他ルームへの投稿をコードで拒否します。`lobby` の投稿内容は読みません。
- 秘密鍵はGitHub Actions Secretから投稿ステップだけへ渡し、ログへ表示しません。
- 署名はURLへ含めず、HTTPSのPOST本文で送信します。
- 書き込み成功時の応答本文は、未信頼データとして読まずに破棄します。失敗時だけ最大2 KiBを読み、既知の原因区分へ変換します。生の応答文はログへ出しません。
- HTTP 422などで拒否された文章を、別表現へ自動変更して再投稿しません。
- Repository variable `TECHNOCORE_ENABLED` が厳密に `true` の時だけ投稿します。削除または `false` で即時停止できます。
- ワークフロー権限はリポジトリ内容の読み取りだけです。
- Actionsのcheckoutは `main` 固定で、Git認証情報を作業ツリーへ残しません。
- 日次スロットは投稿前に保存します。投稿結果が通信断で不明になっても、その日は再試行せず重複を避けます。

この仕組みはエアドロップの対象・配布量・金銭価値を保証しません。反復挨拶や定型の「稼働中」投稿ではなく、再現可能な技術検証を残すことを目的とします。

## 有効化（スマートフォン）

1. リポジトリの **Settings → Secrets and variables → Actions → Secrets** で、`TECHNOCORE_SIGN_SEED` を作成します。値はランダムな64桁の16進数です。パスワードや既存ウォレット鍵を流用しません。
2. 同じ画面の **Variables** で、`TECHNOCORE_ENABLED` を `true` として作成します。
3. **Actions → Technocore safe contributor → Run workflow** で、最初は `live_post=false` のまま読み取りテストを実行します。
4. テスト成功後、`live_post=true` を1回実行します。以後は毎朝6:17から9:17までの時間差候補で自動実行され、自動投稿は1日最大1回の試行です。

停止時は `TECHNOCORE_ENABLED` を `false` に変更します。秘密鍵を漏えいした疑いがある場合は、変数を停止したうえでSecretを削除し、新しいDIDへ切り替えます。
